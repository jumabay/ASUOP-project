# Набор ограничений Cursor для железнодорожной платформы (Java)

## Установка
1. Распакуй архив в **корень текущего проекта Cursor**, где уже лежит `docs/analysis` после 10 этапов. Не заменяй существующую папку `docs` целиком: скопируй только новые файлы и сравни конфликты.
2. Скопируй `.cursor/rules/*.mdc`, `.cursor/skills/*/SKILL.md`, `AGENTS.md` и шаблон `docs/architecture/APPROVALS_TEMPLATE.md`.
3. Открой Cursor -> Customize -> Rules и убедись, что четыре обязательных правила (`00`–`03`) активны; правила для Java, React и Oracle должны подключаться по файлам.
4. Открой Customize -> Skills и проверь, что навыки обнаружены. Вызывай их по необходимости, например `/legacy-research` или `/architecture-gate`.
5. Сначала используй **Plan Mode** с промптом №11. Утверди архитектуру и список изменений. Только после этого запускай Agent Mode на один согласованный этап.
6. Не подключай MCP к боевой Oracle/1С/FTP. Тестовая Oracle — отдельно настроенная read-only учётная запись с минимальными правами.

## Plugins / MCP
На старте: **не устанавливать дополнительные Cursor Plugins и MCP-серверы**. Git, локальный терминал, Java SDK и стандартная тестовая среда достаточны. Плагины добавлять только под конкретную измеримую необходимость после проверки их прав. Для Cursor Marketplace: https://cursor.com/docs/plugins

## Обязательная последовательность
Plan -> подтверждение владельца -> один Agent-этап -> сборка + тесты + сравнение с legacy -> отчёт -> остановка.

## Ключевые запреты
Никаких изменений production Oracle, никаких реальных отправок FTP/1С, никаких самостоятельных деплоев, миграций, массовых запросов, установки инструментов, запуска параллельных агентов или неоговорённого расширения задачи.

## Важное ограничение
Инструкции в Rules/Skills **не являются технической песочницей**: реальную защиту обеспечивают учётные записи с минимальными правами, Git, резервные копии, изоляция тестовой базы и подтверждение опасных действий.
