# ADR-0002. JDBC к пакетам, без JPA на ленте

## Статус

Принято.

## Контекст

Старые клиенты не содержат имён таблиц в вызове среза. Контракт — пакеты `DBTC`. `STATEREPORTRECORDS` по статистике содержит около 1,215 млрд строк, первичного ключа и секций нет. Рядом лежат архивы в сотни миллионов строк. ORM на такой ленте тянет граф объектов и не совпадает с существующим контрактом курсора.

## Решение

Чтение и будущая запись идут через Spring JDBC / `JdbcClient` и `CallableStatement` в единственном шлюзе. JPA не применяется к `STATEREPORTRECORDS`, `WAGONAPPROACHARCHIVE`, `WAGONDOWNTIME`, `GIVINGARCHIVE`, `WAGONMILEAGE`. Произвольный `SELECT` с клиента запрещён. Белый список процедур задан в `05_ORACLE_INTEGRATION.md`.

## Последствия

Курсор пакета вручную складывается в DTO. Это больше кода на процедуру, чем у ORM, и это совпадает с тем, как уже устроена система. Справочники малого объёма тоже читаются через шлюз, чтобы не заводить второй способ доступа.
