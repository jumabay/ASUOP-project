# ADR-0003. Драйвер JDBC 19c к Oracle 12.2

## Статус

Принято с условием smoke-test. Уточнено 2026-11-14: артефакт Maven Central.

## Контекст

Словарь на `tc-asuvp-03` показывает Oracle 12.2.0.1.0. По матрице Oracle JDBC FAQ драйвер 23.x базу 12.2 не поддерживает. Линии 19c и 21c к 12.2 помечены Was: раньше поддерживались, исправления для этой пары больше не обещаны. Страница загрузок линии 19c по-прежнему перечисляет 12.2 среди баз, с которыми работает этот драйвер. Spring Boot 3 требует Java 17 или новее. Драйвер 12.2 `ojdbc8` рассчитан на JDK 8 и с Boot 3 не стыкуется. Premier Support 12.2 закончился.

Ранняя формулировка «`ojdbc11` линии 19c» была ошибочной относительно Maven Central: у артефакта `com.oracle.database.jdbc:ojdbc11` нет версий `19.x` (только `21.x` и `23.x`). Линия JDBC 19c на Central публикуется как `ojdbc8` / `ojdbc10`.

## Решение

До отдельного обновления базы шлюз использует **`com.oracle.database.jdbc:ojdbc10:19.33.0.0`** на Java 21 вместе с **`com.oracle.database.nls:orai18n:19.33.0.0`** (кодировка сессии `CL8MSWIN1251`). Первое подключение — только короткие диагностические `SELECT` (DUAL / системные представления) по отдельному scoped-разрешению. Если соединение не открывается, приложение к Oracle не подключается. Обход через неподдерживаемый драйвер **23.x / `ojdbc11:23.x` не используется**. Целевая база горизонта 10–15 лет — Oracle 19c, окном DBA, не миграцией приложения.

## Smoke-test (2026-11-14)

Условие ADR выполнено: заключительный диагностический прогон успешен. Доказательства и границы разрешения — [21_JDBC_SMOKE_CHECK.md](../21_JDBC_SMOKE_CHECK.md). **Production access** в журнале остаётся `DENIED UNTIL APPROVED`; постоянный allow-list на `tc-asuvp-03` не вводится.

## Последствия

Стек приложения поддерживается. Стек «драйвер + 12.2» поддерживается слабо. Это записано как риск, а не как скрытое допущение. Модули зависят от имён пакетов, не от версии драйвера, чтобы смена драйвера после апгрейда базы не переписывала домен.
