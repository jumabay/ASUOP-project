# 17. Дорожная карта миграции

Порядок задают писатели и общие ключи. Удобство экрана порядок не меняет. Волны совпадают с [08_CROSS_SYSTEM_MATRIX.md](../analysis/08_CROSS_SYSTEM_MATRIX.md). Приложение и база этим документом не создаются.

Технология хоста — Java. Смысл волн от архивного плана на C# не меняется.

## Один писатель

| Агрегат | Владелец, пока волна записи не открыта | Чем опасен второй писатель |
| --- | --- | --- |
| Срез `disl_*` | «Сервис приложение», `ImportPkg` | повтор имени пропустит файл или допишет строки; `CreateJob*` плодит задания |
| Карточка `WAGON` | старый `WagonApp`, `SaveWagon`; локацию может писать `WAGONUPDATEDISL` | расхождение станции нельзя отличить от job |
| Проводка ремонта | УВП, `RepairsPkg.Register` | тело не прочитано, идемпотентность не доказана |
| Проводка склада | НУД, `WarehousePkg.Register*` | делит деталь с ремонтом и не делит документ |
| Пробег и детали 2612/2731 | «Сервис пользователя» | повтор сообщения может задвоить строки (G8, не измерен) |
| Витрины | jobs Oracle | новый пересчёт встанет рядом с ночным job |

Новый хост при старте проверяет, что флаги записи выключены. Если в конфигурации указан живой старый импортёр, процесс писателя среза не поднимает.

## Волны

| Волна | Что переносится | Почему раньше следующей | Что остаётся в старом контуре | Чем открывается |
| --- | --- | --- | --- | --- |
| 0 | Ничего не пишется. Файл разбирается локально | второй писатель в `ImportPkg` может задвоить ленту | «Сервис приложение» — единственный писатель `disl_*` | R0, без Oracle |
| 1 | Справочники только чтением | на них входящие FK документов | старые клиенты продолжают их править | учётка копии |
| 2 | Чтение вагона и среза | карточка и отчёты сидят на `WAGON` и `STATEREPORTRECORDS` | старый НУВ не выключается | A1, A2 |
| 3 | Чтение ремонта и склада | запись ремонта и склада делит `WAGONPARTS` | оба `Register*` не вызываются | A3–A8 |
| 4 | Готовые отчёты по одному | отчёт читает витрину, которую пишет job | конструктор с произвольным SQL не переносится | A9, A10 после ночных jobs |
| 5 | Подача и наряды — чтение | пакет подачи зависит от ленты; кнопки не разобраны | `UpdateStateReport` нарядов и `SaveGiving*` импортёра | закрытие G10 |
| 6 | Запись ремонта, затем запись склада | `TR_REPAIRS_TIME` на каждой правке `REPAIRS` | оба `Register*` до своих тестов | B4, затем B5; B6, затем B7 |
| 7 | Замена импортёра KZ | только после совпадения числа строк и ключей | до этого новый процесс файл только читает | B1 на двух копиях |
| 8 | Экспедирование, финансы, договоры, 1С | требований нет | старый контур этих правил не содержит | отдельное задание |

АСУОП и MSSQL `terminal` в волны не входят. Каналы TIS, контейнеров и Excel остаются на старом импортёре после замены одного KZ.

Параллельно с волнами, отдельным окном DBA: план обновления Oracle 12.2 до 19c. Приложение это окно не открывает. До окна действует правило драйвера из [02_TECHNOLOGY_STACK.md](02_TECHNOLOGY_STACK.md).

## Переключение пользователей

Переключение идёт по роли и экрану. База одна. Обратная выгрузка строк не делается.

1. Роль с правом чтения получает экран React рядом со старым EXE. Старый EXE остаётся установленным.
2. Сверка на копии проходит до показа экрана. Промышленный показ чтения — только после отдельного разрешения смотреть промышленную схему read-only.
3. Экран записи не показывается, пока не пройден тест группы B и нет разрешения на DML в копии.
4. Обратный шаг: роль снова открывает старый EXE. Флаг записи нового модуля выключается. Данные не копируются обратно.
5. Старый EXE выключается для роли только когда эта роль больше не пишет и чтение нового экрана совпало с эталоном. Служба импорта выключается последней, после B1.

ClickOnce старых клиентов при запуске может сходить на сервер обновлений. Демонстрации сверки делаются на копии поставки, которую согласует заказчик. Новый хост ClickOnce не использует.

## Ворота записи

Запись не начинается, пока нет всех пунктов:

- тело `ImportPkg`, включая момент установки `IsImportedFile` (G1–G3, G25);
- объект `WAGONUPDATEDISL` найден под учёткой владельца (G4), либо явно решено, что локация карточки не переносится;
- образец `disl_kz*.txt` и, если он есть у заказчика, образец второго файла часа;
- read-only учётка копии;
- тест B1 на двух копиях для замены импортёра;
- наблюдение G6 для проводки ремонта и склада;
- измерение G8 до любого приёма 2612/2731 новым кодом.

Пробелы G10, G19, G20, G21 и M18 закрывают свои экраны и не держат волны 0–3.

## Откат волны

Волна чтения откатывается выключением экрана роли. Строки не менялись. Волна записи на копии откатывается сбросом копии, не правкой промышленной базы. Волна 7 откатывается остановкой нового писателя и возвратом файла старому импортёру только если новый писатель ещё не стал единственным на промышленной схеме. Промышленное переключение писателя этим документом не назначается.
