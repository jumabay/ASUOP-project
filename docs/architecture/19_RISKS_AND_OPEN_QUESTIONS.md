# 19. Риски и открытые вопросы

Источник пробелов: [08_GAPS_AND_UNCERTAINTIES.md](../analysis/08_GAPS_AND_UNCERTAINTIES.md). Здесь — перечень для архитектуры. Алгоритм по имени процедуры не восстанавливается.

Проверка одна: read-only на копии, старый контур остаётся единственным писателем, промышленный FTP и промышленная сессия не используются.

## Риски параллельной работы

| Риск | Что делать |
| --- | --- |
| Два писателя среза | новый код `Save*` не вызывает |
| Две копии службы перепутаны | config не копировать |
| Частичный час | не чинить дыру повторным прогоном того же имени |
| Ночной job и новый расчёт дат | витрины не пересчитывать |
| Проводка с двух сторон | ни один `Register*` не дублировать |
| Тяжёлый отчёт против импорта | произвольный SQL не исполнять, пул `Report` отдельный |
| Журнал со значениями фильтров и `.brp` | канал не переносить |
| ClickOnce | клиенты в исследовании не запускались |
| Oracle 12.2 вне обычной поддержки | smoke-test JDBC на копии; апгрейд до 19c — окно DBA |
| Драйвер 19c к 12.2 помечен Was | при отказе соединения хост к базе не подключается |

## Чего нет во входе

- Образец `disl_kz*.txt` и образец второго файла часа.
- Read-only учётка копии для прикладного API.
- Подтверждение, что в инфраструктуре есть Active Directory. В клиенте есть имя `DomainConnect`.
- Конфигурация 1С и тестовая база 1С.
- Требования экспедирования, договоров и финансовых операций.
- Срок хранения истории, названный бизнесом. Удаление секций поэтому не проектируется.
- Измеренные ядра и память сервера приложений. В [15_DEPLOYMENT_ARCHITECTURE.md](15_DEPLOYMENT_ARCHITECTURE.md) указана только гипотеза.

## Технический риск стека

Java 21 + Spring Boot 3.5 + Modulith 1.4 согласованы между собой по документации Spring. Согласование с Oracle 12.2 слабое: актуальный JDBC 23.x базу 12.2 не поддерживает. Это принято явно в [ADR-0003](decisions/ADR-0003-oracle-jdbc-19c-against-12-2.md). Платформа на 10–15 лет не должна остаться на 12.2. Код модулей от версии базы зависит только через шлюз.
