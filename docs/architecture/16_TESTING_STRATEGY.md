# 16. Стратегия тестирования

Новая реализация сверяется со старой на одном входе. Эталон — результат старого контура, не формула, восстановленная по имени процедуры. Пока тело пакета скрыто, пройденный тест значит совпадение со старым результатом.

Источник набора: [08_EQUIVALENCE_TESTS.md](../analysis/08_EQUIVALENCE_TESTS.md). Ожидаемые числа заранее не заполняются: клиенты в исследовании не запускались.

## Общие условия

- База сверки — копия, не промышленная `DBTC`. Учётка read-only там, где тест помечен как чтение.
- Старый писатель один. В группе A новый код только читает уже лежащие данные. В группе B новый код пишет только в свою копию.
- Оба писателя в одну базу одновременно не пускаются.
- Порядок строк без `ORDER BY` не сравнивается. Деньги и целые — точно. Даты — до секунды так, как их вернул курсор.
- Подписи Excel и значки в сверку данных не входят.
- Промышленный FTP и промышленная сессия не используются.
- Пароли, строки соединения и текст запроса в протокол прогона не пишутся.

Группа B закрыта, пока не прочитаны тела из пробелов G1, G6, G8 и нет отдельного разрешения на DML в копии.

Инструменты: JUnit 5 для R0 и модульных проверок разбора. Интеграция с Oracle — против выданной тестовой базы, не против промышленной. Testcontainers используется только если заказчик даст образ, совместимый с фактом 12.2; подменять копию случайным контейнером другой версии нельзя. Playwright начинается с первого читающего экрана.

## Проверки R0 без базы

Библиотека `platform-disl-parser` на синтетической фикстуре. Это не группа A и не группа B. Фикстура не заменяет B1 и не заменяет G1. Источник таблицы: перенос смысла из архивного `_archive_csharp/TEST_STRATEGY.md`, §7.

| Проверка | Ожидание |
| --- | --- |
| 20 полей и 21 поле | обе строки разобраны, контейнеры есть только у 21-го поля |
| Пустой файл | журнал часа не получает комплект |
| Две строки с одной станцией | обе остаются в часе |
| Повтор имени и типа | второй комплект в локальном журнале не создаётся |
| Дыра в календаре | пропущенный час перечислен в результате |

Успех R0 открывает только следующий разговор о коде чтения при наличии учётки. Он не открывает волну записи и не закрывает G1.

## Группа A. Чтение

| ID | Функция | Критерий | Сейчас |
| --- | --- | --- | --- |
| A1 | История среза за сутки | Совпадают число строк и ключи курсора `GetWagonStateReports`. Пустой курсор с обеих сторон — совпадение | Ждёт копию и вагон, у которого срез уже есть |
| A2 | Карточка | Совпадают номер, модель, род, собственник, станция приписки, признак инвентаря. Станция карточки в тест не входит | Готов как чтение |
| A3 | Список ремонтов | Совпадают id и вид 0…8 | Готов как чтение |
| A4 | Даты и пробег | Значения `[LoadOnlyField]` равны считанным. Вызовов `ImportMileage*` нет | Готов как чтение |
| A5 | Детали ремонта | Множества id совпадают. Пересечение «после» и «снятые» пусто | Готов как чтение |
| A6 | История детали | Один курсор `LoadPartHistory` и одно число `GetHistoryState` | Готов как чтение. Подпись значка ждёт G16 |
| A7 | Остаток склада | Совпадают ключ детали и количество | Готов как чтение |
| A8 | Реестр документов | Совпадают id и признак проводки. Период не шире 31 дня | Готов как чтение |
| A9 | Готовый отчёт | Совпадают число строк и значения колонок, которые старый клиент пишет в лист | Движение готово как вызов. Реализация ждёт G21 |
| A10 | План погрузки | Курсоры совпадают. Строка «ИТОГО» сравнивается как сумма клиента | Готов как чтение |
| A11 | Анализ | Те же вызовы, что реально делает `ReportsBinder.GetAnalyzeReport` | Заблокирован M18 |
| A12 | Конструктор | Совпадают число строк и значения полей. Новый код склеенный текст не исполняет | Заблокирован G19 |

A2 специально не требует равенства «станция карточки = последняя строка A1». Провал A останавливает перенос соответствующего экрана. Успех A1 не открывает замену импортёра.

| ID | Функция | Критерий | Сейчас |
| --- | --- | --- | --- |
| B1 | Импорт одного файла KZ | Одинаковое число строк и ключи. Повтор имени не добавляет второй комплект | Нет образца, тело `SaveStateReportLineKz` не читалось |

## Порядок

1. R0 на фикстуре, без базы. Фикстура не заменяет B1 и не заменяет G1.
2. A2–A8 на одной копии и одном вагоне, у которого есть ремонт и деталь на складе.
3. A1 на том же вагоне за уже импортированные сутки.
4. A9 и A10 на одном закрытом дне после ночных jobs.
5. Закрыть M18, затем A11. Закрыть G19, затем A12 на копии с периодом.
6. G1–G3 на наблюдении старого импортёра. Затем B1 на двух копиях.
7. B4, затем B5. B6, затем B7. Отдельными разрешениями на DML.
8. B8 не пересекается по времени со старым приёмником 2612.

## Нагрузка

Пороги договорные: их ещё не измеряли. Прогон либо подтверждает порог, либо фиксирует фактическое время и останавливает показ экрана, пока порог не пересмотрен явно.

| Сценарий | Вход | Пул | Договорный порог |
| --- | --- | --- | --- |
| Карточка | один вагон, паспорт и сутки среза | `Ui` | 95-й перцентиль не больше 1 секунды |
| Список | около 18 000 вагонов | `Ui` | 95-й перцентиль не больше 3 секунд, без скана ленты |
| Разбор файла | 18 000 строк KZ | без Oracle на R0 | быстрее часа |
| Отчёт | один закрытый день | `Report` | укладка в таймаут, старый ориентир 60 секунд |
| Соседство | карточка во время разбора | `Ui` | карточка остаётся в своём пороге |

Очередь сообщений добавляется только если разбор на копии не успевает за час или ломает порог карточки.

## Связка теста и включения

| Успех | Что можно включить | Что остаётся закрытым |
| --- | --- | --- |
| R0 | разбор локального файла | любой вызов Oracle |
| A1 и A2 | экраны истории суток и паспорта на копии | `SaveWagon`, замена импортёра |
| A3–A5 | чтение ремонта | `Save*`, `Register` |
| A6–A8 | чтение склада | `Register*` склада |
| A9, A10 | один готовый отчёт роли | остальные отчёты и книги без SQL |
| B1 | обсуждение замены писателя KZ | другие каналы и промышленный DML |
| B4, B5 | запись ремонта на копии | промышленная проводка |
| B6, B7 | запись склада на копии | ремонтный `Register` из склада |

Включение роли на промышленное чтение этим документом не открывается.
