# 10. НУД — номерной учёт деталей

НУД в этой поставке — `WarehouseApp.exe` 1.2.0.29, заголовок «Складское приложение». Клиент Oracle не открывает: вызов идёт на `IDbManagerCall` сервиса. Карточка ремонта читается через `IWagonCall`.

Источник: [06_NUUD_FUNCTIONS.md](../analysis/06_NUUD_FUNCTIONS.md), [06_NUUD_DATA_MODEL.md](../analysis/06_NUUD_DATA_MODEL.md).

## Что подтверждено

Виды документов: 0 покупка, 1 приход, 2 перемещение, 3 списание, 4 ремонт колёсной пары, 5 оборотная ведомость, 6 документ ремонта склада. Документ вида 6 не является строкой `REPAIRS` и не вызывает `RepairsPkg.Register`.

Модели детали: 0 количество, 1 колёсная пара, 2 изготовленная, 3 крышка люка. Экземпляр лежит в `WAGONPARTS`. Уникальность номера в снимке индексов не зафиксирована (G15). Новый код ограничение не выдумывает.

Чтение: `GetDocumentList` (период по умолчанию 31 день), `LoadWarehouseDetails`, `GetHistoryState`, `LoadPartHistory`, `PartsPackage.SearchParts`. Число `GetHistoryState` сравнивается как число. Значок 0/1/2 и метка пустого курсора `New` расшифровке не подлежат, пока не закрыт G16.

Остатки — `WAREHOUSEDETAILS`. Текущие детали на вагоне (`CURRENTPARTS`, около 168 тыс.) отделены от складского регистра. Виртуальный склад `VIRTUALWAREHOUSEDETAILS` (около 659 тыс.) читается через `LoadVirtualDetails`. Кто пишет `AddBeforeToVirtualWarehouse`, из НУД не вызывается (G13). Ведомость нельзя считать самодостаточной.

Единственная ссылка документа склада на id ремонта — строка списания, если ремонт выбран в диалоге. Для типов списания 2…5 панель связанного объекта на форме пустая (M9). Новый экран пустой id не подменяет.

Автономные `SP_ARRIVALWAGONPARTS`, `SP_ARRIVEWHEELPAIR`, `SP_TRANSFERWAGONPART` пишут те же семейства таблиц и клиентом не вызываются. Рабочим API модуля они не являются.

## Меню, которое уже разобрано

Реестр документов открывается правом 24. Карточка — правом 25. Создание, копирование и сохранение — 26. Удаление — 27. Проводка — 28. Остатки — 29. Конструктор — 30, корень `WAREHOUSESVIEW`. Поиск деталей — тот же `PartsPackage.SearchParts`, что в УВП.

Справочники предприятий ремонта, которые меню НУД умеет править, остаются у `WarehouseApp`. Новый модуль `reference` их только читает.

## Новая форма

Модуль `warehouse`. Чтение реестра, остатка и истории — тесты A6, A7, A8. Запись прихода — B6. Списание со ссылкой на ремонт — B7. Складской `Register*` не вызывает ремонтный `Register`.

В Java переносится вызов пакета, не форма копирования как есть: у старого копирования `Id` обнуляется, а `Register_Type` остаётся как у исходного. Что сделает следующее сохранение проведённой копии, не подтверждено (M8). До закрытия M8 копирование в новый UI не включается.

Риски: G6 для проводки, G13 для виртуального склада, G15 для уникальности номера, G16 для значка истории, M9 для пустого `repairid`, общая деталь с ремонтом при двух проводках.
