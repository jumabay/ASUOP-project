# 22. План подготовки R1 (черновик — без реализации)

Статус: подготовка R1 **ограниченно утверждена** (синтетика, A1/A2 only, без Oracle). Детальный план и ADR сборки: [23_R1_A1_A2_IMPLEMENTATION_PLAN.md](23_R1_A1_A2_IMPLEMENTATION_PLAN.md), [ADR-0008](decisions/ADR-0008-gradle-multi-project.md). Исходники R1 **не** создаются, пока ADR-0008 и план 23 не утверждены.

Опора: [20_FIRST_IMPLEMENTATION_PLAN.md](20_FIRST_IMPLEMENTATION_PLAN.md), [16_TESTING_STRATEGY.md](16_TESTING_STRATEGY.md), [17_MIGRATION_ROADMAP.md](17_MIGRATION_ROADMAP.md), [21_JDBC_SMOKE_CHECK.md](21_JDBC_SMOKE_CHECK.md), [APPROVALS_TEMPLATE.md](APPROVALS_TEMPLATE.md).

## Цель R1 (предлагаемый scope)

Первый **читающий** вертикальный срез после R0:

- экран **карточки вагона** и **истории среза за сутки**;
- закрытие тестами **A1** и **A2** на **тестовой / обезличенной** копии Oracle;
- волна миграции **2** (чтение вагона и среза) — только чтение, без записи.

R1 **не** включает: импорт файла в Oracle, DML, замену `ImportPkg`, React-полировку вне необходимого экрана, экспедирование/финансы/1С.

## Что уже есть

| Артефакт | Статус |
|---|---|
| `platform-disl-parser` (R0) | готов; Oracle не трогает |
| JDBC smoke Java 21 + `ojdbc10:19.33.0.0` + `orai18n` к 12.2 | успех (диагностика) |
| Учётка `RAILWAY_READONLY` | существует; права на запись в снимке не найдены |
| Постоянный доступ к `tc-asuvp-03` | **запрещён** (Production access DENIED) |

## Безопасная среда для R1

Допустимые варианты (нужно выбрать один явным решением):

1. **Отдельный TEST-хост** Oracle 12.2 со схемой `DBTC` (предпочтительно).
2. **Обезличенная копия** данных на TEST (вагоны/срезы без ПДн сверх необходимого).
3. Запрещённый по умолчанию путь: промышленный `tc-asuvp-03` — только при **новом** scoped-разрешении в журнале; smoke это разрешение **не** продлевает.

Строка соединения — только env / secret store. В репозиторий не коммитить.

## Предлагаемый состав работ (после утверждения)

| # | Работа | In scope | Out of scope |
|---|---|---|---|
| 1 | Каркас `platform-oracle` (шлюз, пул Ui, bind-параметры, таймауты) | да | запись, Flyway на `DBTC` |
| 2 | Вызовы чтения пакетов для A2 (карточка) и A1 (сутки среза) по белому списку | да | произвольный SQL к ленте |
| 3 | Минимальный `platform-app` (Spring Boot + Modulith) с read API | да | админка, импорт, jobs |
| 4 | Минимальный React-экран карточки + сутки | да | полный UI redesign |
| 5 | Тесты A1/A2 на TEST | да | группа B |
| 6 | Изменения `platform-disl-parser` | нет | — |

Зависимости модулей — односторонние; чужие internal-классы не используются ([02_architecture rules](../..)).

## Необходимые разрешения перед кодом R1

Зафиксировать в [APPROVALS_TEMPLATE.md](APPROVALS_TEMPLATE.md) отдельными строками:

1. **R1 scope APPROVED** — карточка + сутки, только чтение.
2. **TEST Oracle host/service** — явный JDBC URL тестовой/обезличенной базы (не `tc-asuvp-03`, пока не доказано иное и не выдано новое scoped-разрешение).
3. **Read-only учётка на копии** — либо продолжение `RAILWAY_READONLY` на TEST, либо новая учётка с минимумом прав (`EXECUTE` на пакеты чтения + необходимые `SELECT`).
4. **Анонимизированный вагон-эталон** для A1/A2 (номер вагона / сутки, без лишних ПДн в Git).
5. **Создание каталогов** `platform-oracle`, `platform-app`, `frontend` — явное «можно писать код».
6. Production access остаётся **DENIED**, пока не будет отдельного решения.

## Тесты и критерии готовности R1

| Критерий | Доказательство |
|---|---|
| A2 карточка | совпадение с эталоном старого контура на копии (номер, модель, род, собственник, станция приписки, признак инвентаря) |
| A1 история суток | число строк и ключи курсора `GetWagonStateReports` совпадают; пустой курсор с обеих сторон — совпадение |
| Нет записи | в коде R1 нет DML/DDL; флаги записи выключены |
| Нет пром-подключения по умолчанию | конфиг указывает только TEST; `tc-asuvp-03` не в постоянном allow-list |
| Пагинация / лимиты | запросы ограничены; нет `COUNT(*)` по полной ленте |
| Секреты | нет паролей в Git; только env |
| Сборка | focused tests зелёные; smoke JDBC на TEST (не пром) |

Пороги нагрузки (ориентир из [16_TESTING_STRATEGY.md](16_TESTING_STRATEGY.md)): карточка p95 ≤ 1 с на копии — измерить, не выдумывать.

## Альтернативы среды (кратко)

| Вариант | Плюс | Минус |
|---|---|---|
| TEST Oracle 12.2 | паритет версии | нужен DBA / хост |
| Обезличенная копия на TEST | безопаснее для данных | подготовка среза |
| Только моки без Oracle | быстро | не закрывает A1/A2 |

Рекомендация плана: **TEST 12.2 + обезличенный вагон**, без промышленного JDBC в разработке R1.

## Откат

Удаление/немерж модулей R1. База копии не требует отката схемы `DBTC` (только чтение). Промышленная база не затрагивается.

## Блокирующие вопросы

1. Какой **точный JDBC URL** тестовой Oracle? (для фазы R1-S3; синтетический каркас его не требует)
2. Учётка TEST: та же `RAILWAY_READONLY` или новая с `EXECUTE` на пакеты чтения?
3. Для JDBC-паритета позже: обезличенный вагон и сутки; для синтетики используется `SYN-00001`.
4. Scope A1+A2 only — **подтверждено** (2026-11-14).
5. Модули после утверждения ADR-0008 + плана 23 — **разрешены** условиями заказчика.
6. ADR-0008 — **ожидает утверждения**; сборку не менять до APPROVED.
7. Интервал суток A1: утверждён полуоткрытый `[D 00:00:00, D+1 00:00:00)`. TZ — открытый вопрос **R1-Q-TZ** (legacy фиксировал 00:00:00–23:59:59 без доказанной зоны).
