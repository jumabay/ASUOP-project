# 04. Зависимости модулей

Правило: модуль зависит от чужого публичного интерфейса, не от его JDBC и не от его таблиц. Spring Modulith запрещает цикл. Шлюз Oracle — отдельный технический модуль `platform-oracle`. Бизнес-модули не открывают `DataSource` сами.

## Разрешённые рёбра

| Кто | От кого зависит | Зачем | Чего не делает |
| --- | --- | --- | --- |
| `fleet` | `reference` | станция приписки, род, собственник как идентификаторы справочника | не правит `STATIONS` |
| `dislocation` | `fleet` | номер вагона для строки часа | не вызывает `SaveWagon` и не обновляет `LOCATION*` |
| `repairs` | `fleet` | карточка ремонта принадлежит вагону | не вызывает `SaveWagon` |
| `warehouse` | `repairs` | строка списания может хранить id ремонта, если он выбран на старой форме | не вызывает `RepairsPkg.Register` |
| `reports` | публичные запросы `fleet`, `dislocation`, `repairs`, `warehouse` только если отчёт — обёртка их пакета чтения | готовый отчёт чаще зовёт свою процедуру через шлюз | не исполняет текст конструктора |
| `operations` | `dislocation` | календарь часа и карантин файла | в `DBTC` не пишет |
| `movement` | `dislocation`, `fleet` | пакет подачи словарём зависит от `STATEREPORTRECORDS` | запись не проектируется до G10 |
| `expedition` | `fleet` | будущая связь перевозки с вагоном | правил нет |
| `finance` | `expedition` | будущее сопоставление перевозки и начисления | бухгалтерских проводок нет |
| `integration-1c` | `finance` | будущий журнал обмена | формата обмена нет |
| все читатели | `platform-oracle` | вызов пакета из белого списка | свой SQL по ленте |

`reference` ни от одного бизнес-модуля не зависит. `access` ни от одного бизнес-модуля не зависит: право проверяется до входа в модуль.

## Запрещённые рёбра

- `repairs` → запись `warehouse` и обратно. Проводки делят деталь и не делят документ.
- `dislocation` → `ImportPkg`, пока не пройден B1.
- `reports` → пул `Ui` и сессия импортёра.
- `movement` → `RepairsPkg.UpdateGivingDepartureRepair`. Кто вызывает этот член из живого контура, не подтверждено.
- `warehouse` → `RepairsPkg.Register`.
- Любой модуль → автономные `SP_*` и `CreateJob*`.
- `expedition` / `finance` / `integration-1c` → таблицы `DBTC`, пока нет отдельного задания. Каркас не читает промышленную схему «на всякий случай».

## Общие данные, которые модулем не становятся

| Объект | Кто читает | Кто пишет сейчас | Следствие для Java |
| --- | --- | --- | --- |
| `WAGON` | НУВ и УВП, один `WagonLib` | `SaveWagon`; локацию может писать `WAGONUPDATEDISL` | один модуль `fleet`. Отдельной ремонтной базы нет |
| `WAGONPARTS` | УВП и НУД | проводки ремонта и склада порознь | чтение из обоих модулей через свои пакеты. Запись не делится |
| `STATEREPORTRECORDS` | НУВ, отчёты, словарём — подача | только `ImportPkg` | чтение через пакет. Отчёт без периода запрещён |
| `USERS` / `PERMISSIONS` | все клиенты | старый вход | модуль `access`. Коды прав не выдумываются |

Коды прав, уже привязанные к экранам, перечислены в [13_SECURITY_ARCHITECTURE.md](13_SECURITY_ARCHITECTURE.md). Неизвестный код enum в новый каталог не добавляется.

## Порядок появления в коде

Зависимость не реализуется раньше модуля, от которого она зависит.

1. `platform-disl-parser` без модулей Spring. Oracle нет.
2. `access`, `platform-oracle`, `reference`.
3. `fleet`, затем чтение `dislocation`.
4. `repairs`, затем `warehouse`.
5. `reports`.
6. `movement` после G10.
7. Запись `repairs`, затем запись `warehouse`, затем писатель `dislocation`.
8. `expedition`, `finance`, `integration-1c` — после отдельных требований.

Этот порядок совпадает с волнами [17_MIGRATION_ROADMAP.md](17_MIGRATION_ROADMAP.md).
