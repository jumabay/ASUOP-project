# 14. Архитектура интерфейса

Библиотеки: React, TypeScript, Vite, Ant Design, AG Grid Community. Обоснование — [ADR-0005](decisions/ADR-0005-react-antd-ag-grid.md). Картинок и макетов этот документ не содержит.

Интерфейс — одно приложение с боковым меню модулей и рабочей областью вкладок. Это инструмент диспетчера и оператора, не лента виджетов. Первая поставка показывает только те экраны, у которых есть тест группы A. Остальные пункты меню видны как недоступные, без пустых форм.

## Каркас

| Зона | Назначение |
| --- | --- |
| Боковое меню | модули: вагоны, дислокация, ремонт, склад, отчёты, операции. Экспедирование и финансы скрыты, пока нет задания |
| Вкладки | несколько карточек одновременно. Закрытие вкладки не пишет в Oracle |
| Глобальный поиск | номер вагона через `GetWagonByCode`. Результат открывает карточку `fleet` |
| Шапка | пользователь, роль, признак «только чтение». Ошибки фона — значок со ссылкой в журнал `operations` |

Ширина: рабочее место оператора — широкая таблица. Узкое окно сохраняет меню сворачиваемым и не прячет номер вагона. Отдельной мобильной версии в первой поставке нет: сценарии подтверждены для настольного клиента.

Таблицы реестров — AG Grid: колонки можно скрывать, фильтр и сортировка на загруженной странице. Страница списка вагонов не читает ленту срезов. История суток запрашивается отдельно, с обязательной датой.

Экспорт Excel — файл, собранный на сервере из того же DTO, что и таблица. Оформление старого `.xlt` в критерий сверки не входит.

## Карта экранов первой очереди

| Экран | Кто | Модуль | Опора | Тест |
| --- | --- | --- | --- | --- |
| Вход | все | `access` | сверка с `USERS` | право без кода не открывает пункт |
| Реестр вагонов | диспетчер, оператор парка | `fleet` | `GetWagonList` | список, порог в стратегии тестов |
| Карточка вагона | диспетчер | `fleet` | `GetWagonByCode` | A2 |
| История дислокации за сутки | диспетчер | `dislocation` | `GetWagonStateReports` | A1 |
| Список ремонтов и карточка | сотрудник ремонта | `repairs` | `GetRepairList`, `Load*` | A3, A4, A5 |
| Реестр документов склада | кладовщик | `warehouse` | `GetDocumentList` | A8 |
| Остатки и история детали | кладовщик | `warehouse` | `LoadWarehouseDetails`, `LoadPartHistory` | A6, A7 |
| Один готовый отчёт | аналитик | `reports` | процедура отчёта | A9 или A10 |
| Журнал часа и пропуски | сопровождение | `operations` | локальный файл | R0, без Oracle |

Не входят в первую карту, хотя есть в старых программах: подача и уборка (G10), конструктор произвольного SQL, книги `.xlt` без извлечённого запроса (G20), анализ (M18), проводка, правка паспорта, правка станций.

## Сценарии

Диспетчер вводит номер, открывает карточку и вкладку истории за выбранные сутки. Станция карточки и последняя строка истории на экране подписаны по-разному: равенство этих значений не обещается (G3, G4).

Оператор парка открывает реестр слежения как список паспортов, фильтрует колонками сетки и выгружает видимую страницу. Реестр не строится сканом `STATEREPORTRECORDS`.

Сотрудник ремонта из карточки вагона открывает список видов 0…8 и карточку. Проведённая карточка на чтении не имеет кнопок записи. Кнопки «Провести» нет, пока не пройден B5.

Кладовщик открывает реестр за период не шире 31 дня, остаток склада и историю детали. Пустой id ремонта на списании не заполняется автоматически (M9).

Специалист экспедирования в первой поставке рабочего экрана не получает. Пункт появится вместе с требованиями [11_EXPEDITION_ARCHITECTURE.md](11_EXPEDITION_ARCHITECTURE.md).

Длительный отчёт, если процедура не укладывается в порог пула `Report`, ставится в задание того же процесса и показывает статус в `operations`. Отдельный хост отчётов не заводится. Старый `ExecuteReportData` не переносится: он бросает `NotImplementedException`.

## Состояния, которые пользователь видит

Успех чтения, пустой курсор, отказ права, недоступность копии Oracle, пропущенный час файла, ошибка разбора строки файла. Текст исключения Oracle и SQL на экран не выводятся. Код ошибки пишется в журнал и показывается короткой фразой.
