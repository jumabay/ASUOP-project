# 05. Интеграция с Oracle

> **Target store superseded by [ADR-0009](decisions/ADR-0009-raildb-primary-store.md) (Accepted direction, 2026-11-20):** целевое основное хранилище платформы — `RAILDB` / `RAIL_APP`. Схема `DBTC` остаётся источником миграции, сверки и архивом после cutover. Текст ниже описывает **legacy/переносный** контур на `DBTC` до материализации RAILDB; Create/JDBC/migrate по-прежнему только по отдельным APPROVALS.

Хранилище **legacy на переносе** — схема `DBTC`, Oracle 12.2.0.1.0, сессия словаря снималась на `tc-asuvp-03:1521/RAC.WORLD`. Промышленные строки из config старых EXE не используются.

Источник словаря: [02-oracle-schema.md](../analysis/02-oracle-schema.md), [02_ORACLE_TABLES.md](../analysis/02_ORACLE_TABLES.md). Физика ленты — [06_DATA_STORAGE_STRATEGY.md](06_DATA_STORAGE_STRATEGY.md).

## Как ходим в базу

Единственное место строки соединения — `OracleGateway` в `platform-oracle`.

- Чтение: вызов существующей процедуры, курсор в DTO. Инструмент — `JdbcClient` или прямой `CallableStatement`, если сигнатура курсора неудобна для `JdbcClient`.
- Запись: отдельные классы. В контекст Spring не регистрируются, пока флаг модуля выключен.
- Отчёт: пул `Report`, свой таймаут, обязательный предикат даты на корнях `STATEREPORTRECORDS` и `WAGONDOWNTIME`.
- JPA к `STATEREPORTRECORDS`, `WAGONAPPROACHARCHIVE`, `WAGONDOWNTIME`, `GIVINGARCHIVE`, `WAGONMILEAGE` не применяется.

Учётка нового приложения отдельная от `asuvp_thread_01`…`asuvp_thread_04`, `_21` и `_32`. На волнах чтения у неё `SELECT` и `EXECUTE` только на пакеты чтения. Права выдаются по минимуму. Учётки чтения в репозитории нет: её выдаёт заказчик на копию.

## Что подтверждено словарём

- 251 таблица, около 29 пакетов (58 объектов PACKAGE/BODY), 96 view.
- Spec части пакетов читается из `ALL_SOURCE`. `PACKAGE BODY` вызывающему пользователю не виден.
- Партиций нет: `ALL_PART_TABLES` пуст.
- Клиенты в вызовах среза не содержат имён таблиц. Контракт — пакеты.

Пакеты, найденные и VALID в `DBTC`: `ImportPkg`, `StateReportPackage`, `WagonPackage`, `GivingDeparturePackage`, `RemoteGivingDeparturePackage`, `GivingPkg`, `ApproachPkg`, `RepairsPkg`, `RepairBudgetPkg`, `PartsPackage`, `WarehousePkg`, `AsoupPkg`, `WorkListsPkg`, `DownTimePkg`, `sys_TransportPkg`. Имя `AdminPkg` в схеме не найдено.

## Чего шлюз не делает

- Не выполняет DDL.
- Не вызывает `COUNT(*)` по полной ленте.
- Не секционирует и не перестраивает живые таблицы.
- Не запускает `RotateRepairDetails`, `CreateJob*`, выключенный `FILLSTATEREPROTSWAGONSTATIONS`, разовые `UPDATEPS_*`, автономные `SP_*`.
- Не подключается к промышленной базе ради разработки.
- Не пишет в `STATEREPORTRECORDS_TMP`. Это рабочий объект пакета.

## Мониторинг запросов

Медленный вызов фиксируется на стороне приложения: модуль, имя процедуры из белого списка, длительность, успех или код ошибки. Текст SQL и значения фильтров в журнал не пишутся. Порог карточки и списка — в [16_TESTING_STRATEGY.md](16_TESTING_STRATEGY.md). Разбор плана запроса на копии делает DBA отдельным разрешением. Промышленный AWR этим проектом не снимается.

## Обновление версии базы

12.2 вне обычной поддержки. Целевая версия для горизонта 10–15 лет — Oracle 19c, отдельным окном DBA, не силами приложения. До окна шлюз работает только если smoke-test `ojdbc10:19.33.0.0` (+ `orai18n:19.33.0.0`) к 12.2 успешен. **Smoke 2026-11-14 успешен** — см. [21_JDBC_SMOKE_CHECK.md](21_JDBC_SMOKE_CHECK.md). После окна драйвер можно сменить на линию, которая эту версию сопровождает официально. Приложение при этом остаётся на вызовах тех же пакетов: смена драйвера не повод переписывать модули. `ojdbc11:23.x` к 12.2 не берётся.

Разработка и R1 по умолчанию идут против **тестовой / обезличенной** копии. Разовое диагностическое подключение к потенциально промышленному хосту **не** открывает постоянный доступ (журнал: Production access = DENIED UNTIL APPROVED). Постоянный allow-list для `tc-asuvp-03` не создаётся.

Flyway не накатывается на `DBTC`. Если приложению понадобятся таблицы аудита UI или каталога полей, они создаются в отдельной схеме метаданных и только после явного разрешения. Пока такого разрешения нет, журнал часа пишется в локальный файл.
