# Пробелы, несовпадения и риски

Пара к [08_CROSS_SYSTEM_MATRIX.md](08_CROSS_SYSTEM_MATRIX.md). Здесь только то, чего исследование не закрыло, и то, где уже видимый код спорит сам с собой. Недостающий алгоритм не восстанавливается по имени процедуры.

Проверка везде одна и та же по форме: read-only на копии, старый контур остаётся единственным писателем, промышленный FTP и промышленная сессия не используются.

Это свойства старого конструктора. В эквивалентность данных их не включать: новая реализация этот канал не повторяет.

## 3. Общие модули и дубли

Сводка перенесена в матрицу, чтобы не плодить вторую таблицу. Для проектирования достаточно трёх правил:

- НУВ и УВП делят `WagonLib` и каркас ремонта. Отдельная «ремонтная база» не обнаружена.
- НУД и УВП делят `WAGONPARTS` и `PartsPackage`, но не делят проводку.
- Отчёт не имеет своей базы и своей учётки. Он читает ту же сессию службы, которая пишет срез.

## 4. Демонстрации, без которых проектирование записи слепое

Каждая демонстрация — старый клиент или старая служба на копии. Новая система в этих прогонах только читает результат.

| --- | --- | --- | --- |

## 5. Риски параллельной эксплуатации

Старый контур в это время остаётся рабочим. Новый, по уже принятой схеме, сначала только читает.

| Риск | Почему это не теория | Что делать, пока тела не прочитаны |
| --- | --- | --- |
| Два писателя среза | `IsImportedFile` завязан на имя и тип. Второй процесс с тем же именем либо пропустит файл, либо допишет строки, если флаг ещё не стоит. `CreateJob*` плодит задания | Новый импортёр файл читает и сверяет. `Save*` не вызывает |
| Две копии службы перепутаны | Разные маски RU и разные каталоги FTP. Включение импорта на «Сервис пользователя» снимет другой набор | Конфиги не копировать друг в друга |
| Частичный час становится постоянным | TXT без транзакции. Файл уезжает в `processing` и сам не возвращается. Если флаг ставится в начале, повтор не лечит дыру | Не чинить дыру новым прогоном того же файла, пока не закрыт G2 |
| Ночной job и новый расчёт одних дат | `UPDATEALLREPAIRDATES`, `FILLGIVINGREPORTS`, `FILLKPI`, `AVAILABILITY_VIEW_JOB` уже пишут витрины | Новый код эти витрины не пересчитывает. Отчёт читает то, что записал job |
| Запись `WAGON` из нового UI | Карточку правят и НУВ, и УВП. Оперативное положение может писать невидимый `WAGONUPDATEDISL` | `SaveWagon` и прямые обновления локации не переносить в первой волне чтения |
| Проводка с двух сторон | УВП `Register` и НУД `Register*` делят деталь и не делят документ | Ни одну проводку не дублировать новым вызовом |
| Тяжёлый конструктор против импорта | Оба используют `STATEREPORTRECORDS`. Таймаут 60 с закрывает соединение сессии и делает `Thread.Abort` | Новый отчёт не исполняет произвольный текст и не садится на сессию импортёра |
| Сверка «текущей станции» | Расхождение нельзя толковать, пока не виден `WAGONUPDATEDISL` и тело `UpdateStateReport` | В критерии эквивалентности станцию карточки не объявлять равной последней строке среза |
| Повтор сообщения 2612 / 2731 | Идемпотентность не доказана | Новая служба эти сообщения не шлёт, пока старая их принимает |
| ClickOnce | Запуск клиента может сходить на сервер обновлений. Клиент из-за этого не запускался | Демонстрации D4–D7 делать на копии поставки, которую согласует заказчик |
| Журнал и файл отчёта | В журнал пишется полный SQL со значениями фильтров. `.brp` десериализуется без белого списка типов | В новую систему это не переносить и на старой не использовать как канал обмена |

Критерий, после которого старый импортёр можно обсуждать как заменяемый, уже записан в этапе 10: на одном файле совпали число строк и ключи со старым `ImportPkg`, без записи в промышленную БД. Этот критерий не доказывает правило неподвижного вагона, если сам эталонный пакет это правило прячет. Он доказывает только совпадение с эталоном.
