# Этап 1. АСУВП и почасовые файлы

## Что исследовано

- Эталон: `Старая программа/Сервис приложение/.../ApplicationService` (`ApplicationService.exe` 1.0.3.37, `LogName=ASUVPService`).
- Декомпиляция (ilspycmd, PDB, только чтение): `RemoteLib.GivingDepartures.ImportStateReportsFtp` и наследники, `StateReports`, `PlatformStateReports.PlatformStateReportsJob`.
- Операционные ключи `config.json` обеих копий сервиса (секреты не фиксировались).
- VBA `Программы пользователя/НУВ/.../MacrosTemp/Импорт срезов*.bas`.
- `Сервис пользователя/.../tmp/wagons.txt` — 18334 строки.

Образцов `disl_*.txt` в workspace нет. Исходников `.sln` нет. Сервис не запускался, FTP и Oracle не вызывались.

## Подтверждённые факты

Импорт срезов выполняет не `ImportLib` (это UI типов импорта), а задачи `RemoteLib.GivingDepartures`, которые стартуют только в копии «Сервис приложение». Копия «Сервис пользователя» те же импортёры выключает и включает обмен сообщениями 2610/2612/2654/2731.

`ImportStateReportsFtp` (`ITaskStateReportsImporter`):

1. Таймер `FtpStateReportsReceiveInterval` — **секунды** (`_seconds * 1000`). В эталоне значение **45**, в копии пользователя **60**. Это период опроса FTP, не «раз в час».
2. Маска KZ: `disl_kz*.txt`.
3. Пустой файл удаляется и в Oracle не пишется.
4. Иначе: `ImportPkg.SaveImportFile` → `ImportPkg.SaveStateReport` → каждая строка файла → `ImportPkg.SaveStateReportLineKz` → `ImportPkg.UpdateStateReport`.
5. Повтор файла отсекается `Importpkg.IsImportedFile`.
6. В C# нет сравнения с прошлой дислокацией: строка файла всегда уходит в процедуру.

Поля строки KZ (табуляция, индексы 0–20): номер вагона, станция дислокации, индекс поезда, дата дислокации, код операции, станция назначения, станция отправления, получатель, отправитель, тип, собственник, НОД, гружёность, рабочее состояние, номер документа, код груза, вес груза, грузоподъёмность, код сообщения, дата операции, контейнеры (если 21 поле).

Другие включённые импортёры эталона (все пишут каждую строку, фильтр «не двигался» в C# отсутствует):

| Задача | Маска эталона | Тип среза в коде | Процедура строки |
|---|---|---|---|
| `ImportStateReportsFtp` | `disl_kz*.txt` | 0 (поле не инициализировано явно) | `ImportPkg.SaveStateReportLineKz` |
| `ImportStateReportsFtpRu` | `disl_operations*.txt` (у пользователя `disl_cis*.txt`) | 1 | `ImportPkg.SaveStateReportLineRu` |
| `ImportStateReportsFtpTisRu` | `disl_vagons_cis*.txt` | 2 | наследник KZ, та же `SaveStateReportLineKz` |
| `ImportStateReportsFtpTisThirdParties` | `disl_vagons_all_*.txt` | 16 | наследник KZ |
| `ImportStateReportsFtpTisContainers` | `disl_containers_*.txt` | 3 | `ImportPkg.SaveStateReportLineContainer` (пропуск заголовка) |
| `ImportStateReportsXls` | `*_disl_kz.xls` | 23 | `ImportPkg.UpdateStateReportXml`, тип импорта 221 |

`PlatformStateReportsJob.Run` бросает `NotImplementedException`. К почасовым срезам вагонов не относится (заготовка «платформы с MS SQL»).

VBA `ImportModule.Convert` читает лист Excel и собирает XML по всем непустым строкам листов Г_РП/П_РП/Г_НРП/П_НРП. Это отдельный ручной контур, не FTP-импортёр.

`wagons.txt` в копии пользователя: 18334 строки. Это близко к требованию ~18 000 вагонов на слежении. Связь файла с таблицей слежения кодом этого этапа не доказана.

## Бизнес-логика

Сервис забирает текстовые срезы с FTP и складывает файл целиком в Oracle через пакет `ImportPkg`: заголовок файла, затем строка на каждый вагон (или контейнер) файла. Час как бизнес-период в таймере не задан. Если внешняя система кладёт полный список каждый час, сервис сохранит все строки этого файла, в том числе без смены станции. Отбрасывает ли уже Oracle одинаковые строки — в C# не видно.

## Связи

- Схема из config: `dbtc`.
- Чтение истории среза вагона: `StateReportPackage.GetWagonStateReports`.
- Клиенты ходят в Remoting API того же процесса (копия «Сервис пользователя»), не в импортёр.

## Неизвестное

- Тела `ImportPkg.SaveStateReportLineKz` / `SaveStateReportLineRu`: пишется ли строка, если вагон не двигался.
- Какой файл — «полный», какой — «изменения». Маска `disl_operations*.txt` относится к импортёру РФ (тип 1), а не к отдельному дельта-каналу KZ. Пара «полный + изменения каждый час» кодом не доказана.
- Содержимое реального почасового файла (образцов нет).
- Почему тип KZ в поле класса равен 0: статического присваивания нет.

## Риски

- Две копии сервиса нельзя подменять: другой набор задач и другая маска RU.
- Опрос раз в 45 секунд при файлах ~18k строк создаёт риск повторной нагрузки, если `IsImportedFile` не сработает.
- Правило «хранить срез без движения» зависит от PL/SQL, не от клиента.
