# Этап 7. Реверс АСУОП

## Что исследовано

- `Программы пользователя/АСУОП/.../cncClient.exe` 1.0.0.53, продукт «АСОУП Терминал».
- Список классов.
- Имена ключей `cncClient.exe.config` (значения серверов и строки подключения не публикуются).
- Задачи `RemoteLib.AsoupTerminal.*` и `AsoupPkg` в сервисе АСУВП.
- Клиент `ApplicationService.cncServiceReference.WebServiceSoapClient`.

Внешние SOAP и MSSQL не вызывались.

## Подтверждённые факты

`cncClient` — терминал сообщений: `MessageBrowser`, `Messages.Forms`, `AnswerBrowsers`, `DSMessages`, `DSAnswers`. Классов справок по дислокации вагона в списке нет.

Конфиг клиента описывает MSSQL, база в ключе `Database` — `terminal`, не схему Oracle `dbtc`.

Сервис АСУВП параллельно содержит задачи приёма/отправки сообщений 2610, 2612, 2654, 2731 и вызовы `AsoupPkg.LoadWagonsMessages2610`, `LoadWagonsMessages2612`, `SetSendedWagon`. В эталоне «Сервис приложение» включён только приём 2612. В «Сервис пользователя» включены все восемь флагов 2610/2612/2654/2731.

В `WagonApp` (НУВ и УВП) есть пространство `WagonExplorer.Asoup` и `dsWagonsMessages`. Сообщения по вагонам доступны из клиента вагонов, не только из `cncClient`.

## Бизнес-логика

АСУОП в поставке — обмен сообщениями АСОУП/CNC и просмотр ответов. Это не импорт почасовой дислокации и не доказанный модуль «справок по вагонам» из пункта ТЗ. Справки по вагону ближе к `WagonApp` + `StateReportPackage` и конструктору отчётов.

## Связи

- Смежный контур: MSSQL `terminal` + SOAP CNC.
- Пересечение с АСУВП: пакет `AsoupPkg` и задачи `WagonMessage*`.
- Общей транзакции с записью среза `ImportPkg` в коде нет.

## Неизвестное

- Что реально делает SOAP-метод, который вызывает `ApplicationService` (исходник сервиса CNC не в workspace).
- Нужно ли включать АСУОП в первую волну веб-миграции. По файлам это отдельный контур.

## Риски

- Смешение Oracle `dbtc` и MSSQL `terminal` в одной схеме миграции.
- Включение задач 2610/2731 на импортном экземпляре сервиса изменит промышленный обмен. Конфиги не менялись.
