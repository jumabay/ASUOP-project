# Этап 10. Целевая архитектура и миграция

> Снято как целевой стек (журнал [APPROVALS_TEMPLATE.md](../architecture/APPROVALS_TEMPLATE.md), 2026-11-13). Порядок волн и запрет второго писателя остаются фактами исследования. Технология хоста — Java, см. [01_SYSTEM_OVERVIEW.md](../architecture/01_SYSTEM_OVERVIEW.md).

Проект. Код новой системы не создавался. Стек из ТЗ этого этапа, предварительный и более не целевой: C# / ASP.NET Core / .NET 10 / Blazor. Первая волна оставляет Oracle `dbtc` и старые EXE.

## Что обязано сохраниться

Пока PL/SQL не прочитан, новая система не имеет права заменить `ImportPkg`. Приём файла должен повторять факт этапа 1:

- читать все строки файла;
- не выбрасывать вагон из-за отсутствия движения на стороне приложения;
- считать час свойством файла, а не таймера 45 секунд;
- хранить идентификатор файла так, чтобы повтор (`IsImportedFile`) не задваивал срез.

Критерий приёмки среза: за час без операций по вагону в хранилище есть строка этого часа, если она была во входном файле. Проверка — сравнение с результатом старого `ImportPkg` на одном и том же файле, без записи в промышленную БД.

## Контур

```text
FTP / файлы disl_*  →  новый импортёр (только чтение файлов)
                    →  тот же ImportPkg в dbtc, пока пакет не разобран
Старые WagonApp / WarehouseApp / cncClient  →  прежний ApplicationService
Новый Blazor  →  читает те же пакеты чтения (StateReportPackage, WagonPackage, RepairsPkg, WarehousePkg)
```

Параллельная работа: старый импортёр остаётся единственным писателем среза, пока сверка на тесте не покажет совпадение числа строк и ключей. Новый UI сначала только читает.

## Волны

1. Наблюдение. Новый импортёр не пишет в БД. Считает строки `disl_kz*.txt` и сверяет с тем, что уже записал старый сервис (read-only SELECT после разрешения).
2. Чтение. Blazor: список вагонов, карточка, история среза за сутки. Старые клиенты не выключаются.
3. Отчёты. Перенос шаблонов из `НУВ/Templates` по одному, сверка с Excel старого клиента.
4. Склад и ремонт. Экраны поверх `WarehousePkg` и `RepairsPkg` после чтения пакетов.
5. Запись. Подача, документы склада, замена импортёра — отдельные разрешения на DML. АСУОП/MSSQL `terminal` в эти волны не входит: это другой контур (этап 7).

## Пробелы, которые блокируют волну записи

- Нет текста `ImportPkg` и триггеров (этапы 2–3).
- Нет образца полного файла и файла изменений.
- Нет подтверждения, что `disl_operations*.txt` — дельта, а не срез РФ.
- Нет read-only учётки тестовой Oracle. Промышленные строки из config не использовать.
