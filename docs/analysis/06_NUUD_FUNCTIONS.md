# НУД: окна, документы и цепочки вызовов

НУД в этой поставке — клиент `WarehouseApp.exe` **1.2.0.29** (Soft Craft, 2006–2020). Заголовок окна: «Складское приложение». Исходников `.sln` нет.

Разбор сделан декомпиляцией **копий** `ilspycmd` 9.1 (`docs/analysis/_nuud_tmp`). Оригиналы в «Старая программа» не менялись. Клиент не запускался. Пакеты Oracle не выполнялись. Тела `PACKAGE BODY` скрыты: проверки внутри `Register*` / `Save*` названы только там, где их видно в spec или в клиенте.

Схема в `config.json` — `dbtc`. После входа `Session.Current.DbManager` — это `RemoteDbManager`: вызов уходит на `IDbManagerCall` сервиса приложений (ключ `DbManagerCallInterfaceKey`, порт `DbManagerCallPort`). Карточка ремонта вагона читается через `Session.Current.Wagon` → `IWagonCall` (порт `WagonCallPort`). Строку Oracle клиент сам не открывает: выбранная строка соединения передаётся в `Connect` / `SecureConnect` / `DomainConnect` сервиса.

Право — флаг `DirectoriesLib.Items.Users.Operations` (нумерация с `WriteWagon = 1`):

| --- | --- | --- |

| 26 | `CreateWarehouseDocument` | «Создать», «Копировать», «Сохранить» |

## 2. Реестр документов

Колонки: номер (`ID`), состояние проводки (`REGISTER_TYPE`), тип документа (`DOCTYPENAME`), склад, поставщик, дата поставки, тип детали, количество деталей, примечание.

## 3. Карточка документа

Общая форма `DocumentFrm`. Заголовок: «Новый документ…» или «Документ… № {id}».

Сохранить вызывает `ApplyFields`, затем `DBManager.SaveObjectReturn`. Провести и отменить проводку **не** сохраняют карточку перед вызовом: в процедуру уходит уже записанный `Id`. Проведённый документ (`Register_Type == 1`) на форме нельзя сохранить и нельзя провести повторно; снятие проводки доступно. Иконка: 0 незарегистрирован, 1 проведён.

Кнопка «Создать документ с выделенными деталями» есть у документов-наследников `WarehouseDocument` (покупка, приход, перемещение, списание, ремонт склада). Она работает только пока документ не проведён. Выделенные строки переносятся в новое несохранённое окно и удаляются из сетки текущего. У ремонта колёсной пары и оборотной ведомости этой кнопки нет.

Строки документа пишутся связью `Relation`: перед строками `Delete*Details`, затем `Save*Details` по каждой строке, затем `Update*`. `NeedSave = false` означает, что сама деталь (`SaveWheelPair` и аналоги) в этот момент повторно не сохраняется. Новая номерная деталь записывается раньше, из карточки детали: `CountingDetailItemView.SaveItem` → `SaveObjectReturn` детали.

## 4. Покупка

Окно `ProcurementDocumentFrm`, подпись «покупки». Поля шапки: склад, дата поставки, контрагент (`Partner`). Строки — `BuyingDetail`.

Для колёсной пары форма записывает номер, клеймо, год и состояние покупки. Толщину обода и дату освидетельствования этот наследник в объект не переносит, хотя поля на базовой форме нарисованы. Номер колёсной пары ограничен 15 символами, клеймо и клеймо освидетельствования — 5. У изготовленной детали такого ограничения длины в форме нет.

Сохранение строки: `WarehousePkg.SaveProcurementDetails` (владелец, деталь, состояние покупки, количество, клеймо завода, дата, две толщины).

## 5. Приход

Окно `ArrivalDocumentFrm`, подпись «прихода». Шапка: склад и дата. Строки набираются по типу объекта склада (`WAREHOUSEITEMSVIEW`): деталь или металл.

| Модель `PartsPackage` | Что вводится | Запись карточки детали |
| --- | --- | --- |
| 0 количество | количество | `SaveDetail` |
| 1 колёсная пара | номер, клеймо, год, состояние, причина несоответствия, клеймо освидетельствования, дата, две толщины | `SaveWheelPair` |
| 2 номерная изготовленная | номер, клеймо, год | `SaveManufactoringDetail` |
| 3 крышка люка | номер чертежа и количество | `SaveHatchCover` |
| металл (`ObjectType = 1`) | количество | справочник `Metal`, не `WAGONPARTS` |

Строка прихода: `SaveArrivalDetails` (владелец, тип объекта, состояние, причина несоответствия, количество, деталь, клеймо, дата, две толщины).

## 6. Перемещение

Окно `TransferDocumentFrm`, подпись «перемещения». Шапка: склад-получатель (`Warehouse`) и склад-отправитель (`WarehouseFrom`), дата. Смена отправителя при непустом списке спрашивает, очистить ли строки.

«Добавить детали» открывает остаток отправителя (`WarehousePkg.LoadWarehouseDetails`). Без выбранного склада текст: «Выбирите склад отгрузки.» Строка: `SaveTransferDetails` (владелец, тип объекта, количество, деталь, состояние покупки).

## 7. Списание

Окно `WritingOffDocumentFrm`, подпись «списания». Шапка: склад, дата, тип списания (`WRITINGOFFTYPES`), причина шапки (`WRITINGOFFREASONS`), связанный объект.

Константы пакета: 1 продажа, 2 на вагон, 3 списание, 4 на колёсную пару, 5 на металлолом. Клиентский переключатель связанного объекта обрабатывает только продажу: подставляется покупатель (`Partner`), его id пишется в `AssociatedObject_Id`. Для остальных типов панель связанного объекта пустая, id остаётся пустым. Отдельной панели «на металлолом» нет: если в справочнике есть строка с id 5, она попадает в общий пустой вариант.

Ремонт и вагон задаются не шапкой, а строкой. Диалог подбора `WritingOffWarehouseDetailsFrm` показывает остаток склада, причину строки и кнопку ремонта. Ремонт выбирается из `RepairsFrm`, грузится `IWagonCall.LoadRepair`, вагон — `LoadObject` по `OwnerId` ремонта. В строку попадают `repairid`, текст ремонта и код вагона. Если ремонт не выбран, эти поля пустые. Это единственное место НУД, где документ склада ссылается на строку `REPAIRS`.

Строка: `SaveWritingOffDetails` (владелец, тип объекта, количество, деталь, состояние покупки, `repairid`, причина строки).

## 8. Ремонт колёсной пары

Окно `WheelPairRepairDocumentFrm`. Это складской документ, не ремонт вагона УВП.

Шапка: ремонтируемая колёсная пара (выбор только с остатка склада), склад этой пары, тип ремонта (`WHEELPAIRREPAIRTYPES`), дата документа, новые номер, клеймо, дата освидетельствования, завод освидетельствования, две толщины обода. Константы пакета для типа: 1 смена оси, 2 смена колеса. Подписи строк справочника клиент не задаёт.

Подбор пары отсекает металл и модель 0 сообщением «Можно выбирать только номерные детали.» Крышка люка (модель 3) под это условие не попадает. После сообщения форма всё равно запоминает выбранную строку; закрытие идёт дальше без отдельного запрета `DialogResult`.

Строки расхода — детали с остатка (`SaveWheelPairDetails`: владелец, деталь, количество, склад, тип объекта).

## 9. Документ ремонта склада

Окно `RepairDocumentFrm`, подпись «ремонта». Шапка: склад, дата, склад отгрузки. Строки берутся с остатка склада отгрузки (`WarehouseRepairDetailsFrm`) и пишутся `SaveRepairDetails` тем же набором полей, что приход.

`RepairsPkg.Register` эта форма не вызывает. Общего поля «id ремонта вагона» на шапке нет.

## 10. Оборотная ведомость

Окно `DetailsWorkingSheetFrm`. Шапка: склад, дата начала, дата конца.

«Добавить детали» читает `PartsPackage.LoadVirtualDetails(warehouse, begin, end)` и заполняет сетку. Колонки набора: тип прихода, id детали, номер, клеймо, тип, год, клеймо завода, id ремонта, id и описание зависимого документа, дата операции. Сохранение шапки — `SaveDetailsWorkingSheet`, затем каждая строка отдельно `SaveDetailsWorkingSheetPart`. Процедуры очистки строк перед повторным сохранением клиент не вызывает.

`PartsPackage.AddBeforeToVirtualWarehouse` из НУД не вызывается. Кто наполняет виртуальный склад, по кнопкам этого клиента не видно.

## 11. Остатки и история детали

Окно « Склад деталей» (`WarehouseExplorerFrm`). Фильтр по складу и типу объекта включён по умолчанию. Чтение: `WarehousePkg.LoadWarehouseDetails`. Колонки сверх общей сетки деталей: склад, состояние покупки. Кнопка Excel выгружает сетку, Oracle не меняет.

Значок истории — `PartsPackage.GetHistoryState(id)`. Клиент подставляет число как индекс картинки: 0 зелёная, 1 красная, 2 серая. Щелчок открывает `PartHistoryFrm` («История детали») и читает `PartsPackage.LoadPartHistory`. Колонки курсора, которые сетка показывает: `history_date`, `history_text`. Пустой курсор форма помечает как `HistoryState.New` (0), непустой — `Used` (1). Совпадает ли код `GetHistoryState` с этими двумя значениями, тело функции не показывает.

Отдельной команды «изменить статус детали» нет. Состояние детали — справочники `DETAILSTATES` и `BUYINGSTATES` на строке документа. Состояние документа — проводка 0/1.

## 12. Чего в клиенте нет

- Документа «возврат». Снятие проводки — `Unregister*`. `PartsPackage.ArrivalRemovedDetails` / `WriteOffRemovedDetails` с кнопок НУД не вызываются.
- Места хранения мельче склада.
- Проверки уникальности номера перед записью. Сообщение «уже существует» в `WagonLib` относится к файлу отчёта, не к номеру детали.
- Вызовов `SP_ARRIVALWAGONPARTS`, `SP_ARRIVEWHEELPAIR`, `SP_TRANSFERWAGONPART`. Это отдельные процедуры загрузки, не кнопки НУД.
- Вызова `RepairsPkg.Register` и записи строки `REPAIRS` из карточки склада.
- Проводки складского документа из карточки ремонта УВП (это уже зафиксировано в разборе УВП).
